# Password recovery setup

Password recovery is implemented but disabled in the current deployment. The sign-in screen will not offer a reset until the application is explicitly enabled with a Cloudflare Email Sending binding and a sender address. Email confirmation remains disabled for the development environment.

Before enabling recovery, the operator must configure and verify a sending domain in Cloudflare Email Service, ensure the account's plan permits sending to all intended member addresses, and verify actual delivery to a controlled mailbox. Cloudflare's [pricing](https://developers.cloudflare.com/email-service/platform/pricing/) states that sending to arbitrary recipients requires Workers Paid; verified destination addresses are available on Free. Do not put member data or real reset links in logs or tickets.

After those prerequisites are satisfied, configure a Cloudflare Email Sending binding named `EMAIL`, set `PASSWORD_RESET_FROM` to the verified sender address and set `PASSWORD_RESET_ENABLED` to `true` in the Worker configuration, regenerate Worker types, build and deploy. The sender must belong to the verified domain. The configured `BETTER_AUTH_URL` must be the app's trusted origin. Leave the feature disabled if any prerequisite is missing.

The reset request returns the same message for known and unknown accounts. The reset link uses a URL fragment so the token is not sent as part of the page request. The form removes the fragment from browser history, and dynamic responses are private and not cached. Better Auth controls expiry (30 minutes), single use and session revocation; the new password must have 12–128 characters. Sending errors are logged generically without the address, link, token or provider error. The message asks the user to contact an administrator if the link does not arrive.

Automated tests use Node SQLite and a fake email binding. An additional isolated local Worker check used a disposable Cloudflare D1 database and simulated email delivery: it verified neutral responses for known and unknown accounts, password length, session revocation, replay rejection, expired-token rejection and exactly one successful concurrent use. No email was sent externally. Better Auth's rate limiter also returned HTTP 429 during repeated test requests; separate scenarios cleared only the disposable database's rate-limit rows.

Before real-member use, verify the complete flow with a controlled real mailbox, including provider failure, disabled-feature behavior and delivery. Cloudflare documents [local email simulation](https://developers.cloudflare.com/email-service/observability/local-development/sending/) and its [Workers email API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/). Email recovery does not enable or replace the separate email-verification step required before real-member onboarding. On D1, Better Auth executes token consumption, session revocation and password update without a database transaction; if a later step fails the token may be spent, so the member may need to request a new link.
